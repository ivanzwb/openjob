# OpenJob 使用手册

> 适用对象：正在使用 OpenJob 做面试准备的用户。  
> 目标：帮助你从第一次打开工具开始，完成“简历整理 → 目标岗位诊断 → 学习计划 → 讲解标注 → 练习复盘 → 话术沉淀 → 多端同步”的完整流程。

---

## 1. OpenJob 是什么

OpenJob 是一个面向具体面试场景的备考工具。它不是简单的资料收藏夹，也不是单次问答工具，而是围绕一场面试，把你要准备的内容拆成可执行步骤：

1. 录入简历和目标岗位。
2. 让系统根据 JD 与简历诊断可能被问到的知识点。
3. 生成学习计划和每日任务。
4. 对知识点生成讲解、做标注、继续细化。
5. 用“考我”和模拟面试检验掌握度。
6. 把真正能在面试里说出口的表达存入话术库。
7. 在桌面端和手机端之间同步，随时继续学习。

OpenJob 的核心目标是：**把准备过程持续转化为自己的面试表达资产**。

---

## 2. 推荐使用节奏

如果你是第一次使用，建议按下面的顺序走：

1. **先建简历**：导入或手动录入你的简历，确认结构和导出效果。
2. **再建目标岗位**：录入公司、岗位和 JD。
3. **开始诊断**：让系统生成知识点树、学习计划和公司情报。
4. **每天按任务推进**：学习讲解、做“考我”、完成复盘。
5. **持续沉淀话术**：把好表达、兜底话术、答题优化稿存入话术库。
6. **手机端同步复习**：把数据同步到手机，利用碎片时间看讲解和话术。

一个简单有效的日常节奏是：

> 每天学 1-3 个点，练 1 次，存 1 条自己的话术。

## 3. 桌面端快速开始

### 3.1 下载与安装

OpenJob 已提供安装包，普通用户不需要从开发环境启动。

下载入口：

- 打开 GitHub Releases 页面：<https://github.com/ivanzwb/openjob/releases>
- 选择最新版本。
- Windows 用户下载 `OpenJob-Setup-*.exe` 安装包。
- macOS 用户下载对应的 macOS 安装包。

安装完成后，直接从系统应用列表或桌面快捷方式打开 OpenJob。

如果 Windows 提示“无法识别的发布者”或 SmartScreen 拦截，可以点击“更多信息”→“仍要运行”。这是因为当前安装包未做商业代码签名，不代表安装包一定有问题；建议只从官方 GitHub Release 下载。

### 3.2 首次配置

第一次使用建议先进入 **设置** 页完成以下配置：

1. **LLM Provider 与 API Key**
   - 填写 OpenAI 兼容接口的 Base URL、模型名和 API Key。
   - API Key 会通过系统安全能力加密保存。

2. **搜索服务**
   - 如需联网检索公司情报、面经或资料，可配置搜索 Provider。

3. **外观主题**
   - 默认浅色。
   - 可在“设置 → 外观”切换深色 / 浅色。

4. **同步**
   - 如果要使用手机端，在桌面端设置页生成配对码或二维码。

## 4. 核心概念

### 4.1 目标岗位

目标岗位保存一次面试准备的基础输入，包括：

- 公司名称
- 岗位名称
- JD 原文
- 相关备注

后续诊断、简历优化和学习计划都会围绕目标岗位展开。

### 4.2 简历

简历是可复用资产。你可以维护一份母版简历，再针对不同目标岗位生成优化版。

常见操作：

- 手动编辑简历字段
- 导入文件
- 使用结构化表单维护工作经历、项目经历、教育经历
- 选择模板预览
- 导出 PDF

### 4.3 备考战役

一场备考战役可以理解为：

> 我针对某个公司和岗位，在某段时间内要完成的一套准备计划。

它包含：

- 目标岗位
- 关联简历
- 知识点树
- 每日计划
- 练习记录
- 话术沉淀
- 面试复盘

### 4.4 知识点

系统会根据 JD 和简历生成知识点树。知识点通常会被分成不同准备优先级：

- **必深挖**：简历写了，JD 也要求，面试中最容易被追问。
- **短板**：JD 要求，但简历没有体现，需要补足框架。
- **雷区**：简历写了，但岗位不一定要求，容易被顺嘴一问问崩。
- **加分项**：相关但非核心，有余力再准备。

### 4.5 话术

话术是你最终在面试中能说出口的表达。它可以来自：

- 知识点讲解
- 划词细化
- 模拟面试反馈
- 真题练习改进稿
- 源码阅读总结

建议定期打开话术库，把机器生成的内容改写成自己的表达。

## 5. 简历中心使用指南

### 5.1 创建或导入简历

进入 **简历** 页后，可以：

1. 新建简历。
2. 从文件导入。
3. 手动编辑结构化字段。

简历字段通常包括：

- 基本信息
- 求职意向
- 工作经历
- 项目经历
- 教育经历
- 技能
- 自定义字段

### 5.2 编辑结构化字段

简历编辑器支持分区编辑。每个分区里可以：

- 添加条目
- 删除条目
- 上移 / 下移条目
- 编辑项目 bullet
- 添加自定义字段
- 使用月份选择器填写起止时间
- 对部分内容使用 AI 优化

建议写简历时保持每条经历的结构清晰：

- 背景：做了什么系统 / 项目
- 动作：你具体负责什么
- 技术：用了哪些关键技术
- 结果：性能、效率、规模、业务指标有什么变化

### 5.3 AI 优化简历

在目标岗位明确后，可以生成定向优化版简历。建议流程：

1. 先维护一份真实、完整的母版简历。
2. 选择目标岗位。
3. 点击生成优化版。
4. 对比优化建议，不要直接全盘接受。
5. 手动改成真实且你能解释清楚的版本。

注意：AI 优化不应该夸大经历。面试官可能会围绕优化后的每句话追问。

### 5.4 预览与导出 PDF

简历支持模板预览和 PDF 导出。导出前建议检查：

- 首页信息是否完整
- 时间线是否一致
- 项目 bullet 是否过长
- 页面分页是否自然
- 联系方式是否正确
- PDF 中中文、英文、标点是否显示正常

## 6. 目标岗位与备考流程

### 6.1 新建目标岗位

在备考相关页面新建目标岗位时，建议至少填写：

- 公司
- 岗位
- JD 原文

JD 越完整，诊断越准确。如果 JD 很短，可以补充：

- 招聘页面链接
- 你了解到的技术栈
- 面试轮次信息
- 面经或岗位重点

### 6.2 开始诊断

点击开始诊断后，系统会尝试：

1. 解析 JD 的技能要求。
2. 解析简历中的项目和技术栈。
3. 交叉分析可能被问到的知识点。
4. 生成知识点树。
5. 生成学习计划。
6. 检索公司情报和面经（如果配置了搜索能力）。

诊断完成后，不建议马上全部展开细学。先看整体结构：

- 哪些点是必深挖？
- 哪些点是短板？
- 哪些点来自简历雷区？
- 哪些点可以暂时跳过？

### 6.3 知识点树

知识点树是你的备考地图。常见操作：

- 查看知识点
- 细化子节点
- 编辑节点名称
- 删除不相关节点
- 添加自己的节点
- 收藏重点节点
- 标记学习状态

如果系统生成了不准确的知识点，可以直接修改。OpenJob 的设计假设是：**AI 负责给初稿，用户负责校正方向**。

---

## 7. 学习计划与每日任务

### 7.1 每日任务

每日任务可能包括：

- 学习新知识点
- 回顾旧知识点
- 做“考我”
- 阅读源码
- 生成兜底话术
- 复盘盲区

建议每天打开后先看今日任务，不要从知识点树里随意跳着学。

### 7.2 完成、跳过与顺延

如果当天任务完成，点击完成。  
如果今天时间不够，可以跳过或顺延。

顺延不是失败，而是让系统重新安排后续节奏。比起硬撑完成，更重要的是保持真实进度。

### 7.3 日历视图

日历视图用于查看：

- 哪天有哪些任务
- 哪些任务已完成
- 哪些任务延期
- 计划是否过密

如果连续几天任务堆积，建议减少学习目标，优先准备高概率、高风险知识点。

## 8. 讲解与标注

### 8.1 讲解档位

知识点讲解通常有不同档位：

- **一句话**：快速建立概念。
- **口语稿**：适合面试时直接表达。
- **深挖**：用于准备追问、原理、取舍。

推荐用法：

1. 先看“一句话”，确认方向。
2. 再看“口语稿”，建立可说出口的版本。
3. 对必深挖知识点再看“深挖”。

### 8.2 重新生成讲解

如果讲解不符合你的场景，可以重新生成，并输入本次要求，例如：

- 多结合我的项目经历
- 少讲源码，多讲面试表达
- 按 2 分钟回答组织
- 重点讲风险和取舍

重新生成会覆盖当前档位的内容。手动修改过的内容重新生成前要谨慎。

### 8.3 划词高亮

在讲解中选中一段文字，可以进行高亮。高亮适合标记：

- 面试必背句
- 容易混淆点
- 关键定义
- 项目关联点

同一段高亮不会重复新增，会更新已有高亮。

### 8.4 记笔记

选中一段讲解后可以记笔记。笔记适合记录：

- 你自己的理解
- 和项目经历的关联
- 面试时要补充的例子
- 尚未弄懂的问题

同一段选区的笔记只允许做一次，避免重复标记堆积。想重写时，先删除旧笔记。

### 8.5 细化讲解

如果某个词、概念或句子不够清楚，可以选中后点击细化讲解。系统会针对这段内容生成更细的解释，并作为内联标记保存。

同一段选区的细化也只允许做一次，避免重复生成内容。

### 8.6 存入话术库

当你看到一段可以直接用于面试表达的内容，可以选中并存入话术库。

适合存入的话术包括：

- 项目介绍中的关键表达
- 技术原理的两分钟回答
- 不熟悉技术的兜底说法
- 模拟面试后的改进稿

同一段内容不会重复存入话术库。

## 9. 考我、模拟面试与复盘

### 9.1 考我

“考我”用于检验你是否真的掌握了知识点。建议不要只看讲解，要定期做考我。

一次考我的典型流程：

1. 系统出题。
2. 你用文字或语音回答。
3. 系统评分并给反馈。
4. 系统指出遗漏点和表达问题。
5. 你把有价值的改进表达存入话术库。

### 9.2 模拟面试

模拟面试更适合练完整回答，而不是单个知识点。

建议使用场景：

- 面试前 1-2 天
- 想练系统设计或项目深挖
- 想检查表达是否自然
- 想发现临场表达盲区

### 9.3 盲区反馈

如果某类问题反复答不好，可以把它视为盲区。处理方式：

1. 回到对应知识点。
2. 看深挖讲解。
3. 记自己的笔记。
4. 再做一次考我。
5. 形成一条更稳的话术。

## 10. 公司情报与面经

如果配置了联网搜索，OpenJob 可以辅助生成公司情报和面经资料。

常见信息包括：

- 公司业务和近期方向
- 可能涉及的技术栈
- 面试流程
- 常见题型
- 可用于反问的问题

生成出来的情报卡分技术栈、面试流程、高频考点、反问素材四节，电脑端和手机端都能看，
手机端默认收起，点标题展开。

使用建议：

- 不要把公司情报当成事实唯一来源。
- 面经适合辅助判断考察频率，不适合逐题背答案。
- 面试前一天重点看“高频 + 自己短板”的交集。

### 10.1 重新生成前会先问一句

已经有结果之后，按钮会从「开始诊断」「公司情报」变成「重新诊断」「重新检索情报」，点了会先弹确认：

- **重新诊断**：新的考点清单会整体替换旧的，考点上的学习状态、收藏和笔记跟着一起没。真要重来再确认。
- **重新检索情报**：只覆盖情报卡本身，不动考点。

这两个按钮挨得近，确认这一步就是防手滑。诊断中途失败不会动到已有的考点清单——要么整体换成新的，要么原样留着。

## 11. 源码与仓库功能

桌面端支持添加代码仓库，用于源码理解和代码问答。

### 11.1 添加仓库

在源码相关页面添加仓库地址后，系统可以：

- 克隆仓库
- 建立文件索引
- 生成项目摘要
- 支持围绕代码文件提问

### 11.2 源码阅读建议

源码任务不建议泛读。更有效的方式是：

1. 先让系统总结模块结构。
2. 找到和岗位相关的技术点。
3. 针对关键文件提问。
4. 把可以面试表达的结论存入话术库。

### 11.3 手机端源码快照

桌面端索引后的源码快照可以同步到手机端。手机端不会克隆仓库，但可以在同步后读取已同步的源码内容。

注意：源码快照体积可能较大，手机端同步前会检查剩余存储空间。空间不足时会跳过源码文件同步，并在同步页提示。

## 12. 话术库使用指南

### 12.1 话术库的作用

话术库不是收藏夹，而是你的面试表达素材库。

它应该沉淀：

- 技术点回答
- 项目经历表达
- 兜底说法
- 模拟面试改进稿
- 源码阅读总结
- 反问素材

### 12.2 如何维护话术

建议定期做三件事：

1. **删重复**：内容相近的只保留最好的一条。
2. **改口语**：把书面表达改成你自然会说的话。
3. **补例子**：尽量把技术点挂到自己的项目经历上。

### 12.3 导出

话术库支持导出，便于：

- 面试前集中背诵
- 制作 Anki 卡片
- 归档备份
- 分享给自己的其他设备

## 13. 手机端使用指南

### 13.1 手机端适合做什么

手机端适合碎片时间使用：

- 看每日任务
- 学习讲解
- 划词高亮
- 记笔记
- 细化讲解
- 做考我
- 查看话术
- 导出或查看简历

桌面端更适合：

- 创建目标岗位
- 大段编辑简历
- 添加仓库
- 做复杂配置

### 13.2 配对同步

推荐流程：

1. 桌面端进入 **设置 → 同步**。
2. 生成配对码或二维码。
3. 手机端进入 **同步** 页。
4. 扫码或输入配对信息。
5. 点 **同步**。

同步只有一个按钮，不需要你选「增量」还是「全量」——首次配对、上次同步失败、或者距上次全表对账超过一周时，程序会自己做一次全表对账。同步完成后两端数据一致，具体哪些数据会过去见 13.3。

### 13.3 哪些数据会同步

**你自己产生的东西，全部同步。** 逐项列一下：

- **简历**：简历母版、针对各个目标岗位的优化版、排版样式和寸照。
- **目标岗位与备考战役**：公司、岗位、JD 原文与解析结果。
- **考点清单**：整棵考点树，连带每个考点的难度、考察概率、优先级、掌握度和学习状态，以及考点之间的前置/相关/对比关系。
- **讲解**：三档深度的讲解正文。
- **追问**：追问会话和里面的每一条消息。
- **考我**：每次作答、评分和改进稿。
- **模拟面试**：题目、评分标准、你写的作答和参考答案。
- **公司情报**：技术栈、面试流程、高频考点、反问素材。
- **面经**：原文，以及从里面拆出来的题目和它匹配到的考点。
- **计划**：每天的排期和排期里的任务。
- **标记与笔记**：高亮、笔记、收藏状态。
- **话术库**：包括你手动编辑过的版本。
- **源码**：仓库的索引状态、摘要、代码引用，以及索引时快照的源码文件（手机端就是靠这份文件读源码的）。
- **设置与 API Key**：整份同步，所以手机端能独立调用 LLM，不需要电脑在线。

**不同步的只有三类，都不是你的数据：**

- **联网检索的缓存**：两端各自重建就行，传过去纯属浪费流量。
- **同步自己的记账**：变更日志、配对信息、同步记录、覆盖留痕。这些描述的就是「这台设备和对端各自进行到哪儿」，两端本来就该不一样。
- **本机专属的一个字段**：仓库克隆到本地哪个目录。这个路径在手机上不存在，传过去没有意义；同一个仓库的其它信息照常同步。

**快照文件也不同步**：两端各自备份、各自回退，互不影响（见 13.5）。

### 13.4 两边改了同一处数据会怎样

不会弹窗要你选，也不会卡住不同步。规则很简单：

- 两边改的是同一条数据的**不同字段**：两边的改动都保留。
- 两边改的是**同一个字段**：**改得晚的那一份生效**，被覆盖的旧值记在同步页的「同步留痕」里，可以看到是哪个字段、哪一边赢了、被盖掉的是什么。
- 一边删除、另一边修改：同样按时间算，晚的那个动作生效。

比较用的是数据的实际修改时间，两台设备系统时间有几秒偏差不影响判断。

### 13.5 快照与回退

**两端各自备份、各自回退。** 电脑端的快照存在电脑上，手机端的快照存在手机上，互相不知情也不需要对方在线。要回退就在哪一端出问题就回退哪一端。

什么时候会自动留一份：

- **同步前**：真正写入数据之前留一份。两种情况不新建：没有数据要写入的空轮不备份（手机端最短 60 秒同步一次，每次复制整个库只会白耗电，空轮也没什么可退的）；距上一份同步前快照不到 15 分钟时复用那一份。复用的代价是回退可能多丢十几分钟的本机改动，换来的是可回退范围从十几分钟拉长到几天——数据不对往往是隔天才发现的，那时候能退回去比精确到分钟重要得多。
- **升级数据库结构前**：装了新版本、第一次打开时如果发现要改数据库结构，会先留一份再改。这一份是「升级不丢数据」的兜底。
- **回退前**：回退本身也会先把当前状态留一份，所以回退错了还能再退回来。

也可以随时手动留一份：电脑端 **同步页 → 本机整库快照 → 立即备份**，手机端 **同步页 → 同步留痕 → 立即备份**。重装、清数据、手工改配置之前建议手动来一份。

回退方式：找到那一份，点 **回退到这份**（手机端）或 **回退**（电脑端）。

旧快照会自动清理，不会越攒越多。清理时机是「新建快照之后」和「每次启动应用」。保留规则三条叠加：

- **同步前的快照**：先无条件留最近几份（电脑端 6 份、手机端 3 份），再按天各留一份最新的（电脑端往回 14 天、手机端 5 天）。所以既能退到几分钟前，也能退到上周某天。只按份数留是不够的：一天同步几十次的话，"最近 N 份"全是最近几分钟的，昨天以前的现场一份都不剩。
- **升级前、手动、回退前**：每一类各自单独计数（电脑端各 3 份，手机端各 2 份），不和同步前的快照抢额度——否则升级后几次同步就能把升级前那一份挤掉，兜底也就没了。
- **总体积上限**：所有快照加起来超过上限（电脑端 4GB，手机端 1GB）就从最旧的开始删，直到降下来。一份快照是整个库的拷贝，如果你同步了源码，单份可能几百 MB，光限制份数管不住磁盘。

有一个例外：每一类**最新**的那一份永远不删，哪怕总体积已经超了。它们各自是一条退路的终点（最新的「同步前」用来撤销刚才那次同步，最新的「升级前」用来回到升级之前）。如果你的库本身就很大、几份就超了上限，实际占用会略高于上限——留住退路比守住数字重要。

### 13.6 升级会不会丢数据

不会，而且有明确的兜底。

新版本如果需要改数据库结构，第一次打开时会先自动留一份**升级前**的整库快照，再动结构。这个动作挂在「打开数据库」上，所以不管新版本是应用内更新、侧载 APK 还是自己重新构建装上去的，都会走到。

如果快照没做成（通常是磁盘或手机存储不够），应用会**拒绝升级数据库结构**并提示你腾空间，而不是硬着头皮改。此时数据还是原样，腾出空间重新打开即可。

升级后如果发现数据不对，去同步页找那份「升级前」的快照回退。要注意的是：回退后数据库结构也回到了旧版本，这时应该配合装回旧版本应用使用。

### 13.7 两端版本不一样

如果桌面端和手机端不是同一个版本，同步会**直接停下来并提示你**，不会交换任何数据；未配对时也无法完成配对。

这是有意为之：不同版本的数据库结构可能已经不一样，硬同步的风险不是「报个错」，而是悄悄把数据写坏。

处理办法：把落后的那一端升级到相同版本。升级完不用重新配对，同步会自己恢复。

- 手机端升级：同步页下方的 **应用更新**（见 13.8）。
- 桌面端升级：**设置 → 更新**。

提示里会写明两端各自的版本号，照着把小的那个升上来即可。桌面端通常会自动更新，所以多数时候是手机端落后。

### 13.8 应用更新

手机端同步页包含应用更新入口。它会检查 GitHub Release 中是否有新版。

Android 上可下载 APK 并唤起系统安装器。  
iOS 上通常只展示版本信息和发布页面入口。

注意：安装新版本可能需要系统授权“允许安装未知应用”。

## 14. 设置与配置

### 14.1 LLM 配置

LLM 是以下功能的基础：

- 诊断 JD 与简历
- 生成知识点讲解
- 细化讲解
- 考我评分
- 模拟面试反馈
- 简历优化
- 话术改写

如果这些功能失败，优先检查：

- API Key 是否正确
- Base URL 是否可访问
- 模型名是否存在
- 网络是否可用
- Provider 是否兼容 OpenAI API

- 公司情报
- 面经检索
- 背景资料
- 外部参考信息

### 14.4 更新检测

桌面端可检查官方 GitHub Release 中的新版本。  
如果发现新版，可以按提示下载或安装。

### 第 1 天：建立基础

## 16. 常见问题

### 16.1 为什么生成的知识点不完全准确？

知识点来自模型对 JD 和简历的理解，可能存在误判。建议把它当成初稿：

- 明显不相关的删掉。
- 缺失的手动补上。
- 重要但不够细的点点击细化。

### 16.2 为什么不建议直接背 AI 生成内容？

因为面试官会追问你的真实经历。AI 生成内容适合当初稿，你需要改成：

- 符合自己经历
- 自己说得顺
- 经得起追问
- 不夸大事实

### 16.3 同一段文字为什么不能重复记笔记或细化？

为了避免同一段内容反复生成重复标记。  
如果你想重写，先删除原来的笔记或细化标记，再重新操作。

### 16.4 手机端能不能离线用？

同步完成后，业务数据保存在手机本地。只要 LLM Provider 可访问，手机端可以独立使用很多能力，不依赖电脑在线。

### 16.5 为什么源码文件没有同步到手机？

源码快照体积较大。手机端同步前会检查剩余空间，如果空间不足，会跳过 `repo_file` 同步，并在同步页提示。

### 16.6 提示「版本不一致，已停止同步」怎么办？

两端不是同一个版本时会拒绝同步，以免把数据写坏。把提示里版本号较小的那一端升级到相同版本即可，不需要重新配对。详见 13.7。

### 16.7 PDF 导出分页不理想怎么办？

建议先检查：

- 单条经历是否过长
- bullet 是否太多
- 模板是否适合当前内容长度
- 是否有大段无换行文本

必要时压缩项目描述，或换更紧凑的模板。

### 16.8 更新检查失败怎么办？

可能原因：

- 网络无法访问 GitHub
- GitHub API 限流
- 当前版本已经是最新
- 手机端没有安装新版本所需权限

可以稍后重试，或手动打开 GitHub Release 页面下载。

## 17. 最佳实践

### 17.1 不要把 OpenJob 当成资料库

资料越多不等于准备越好。真正有用的是：

- 哪些点最可能被问
- 哪些点你答不好
- 哪些表达你能稳定说出来

### 17.2 每天都要产出话术

建议每天至少沉淀一条：

- 一个项目介绍
- 一个技术点回答
- 一个兜底说法
- 一个模拟面试改进稿

### 17.3 标注要少而准

不要整段整段高亮。高亮应该用于：

- 关键定义
- 面试可复述句
- 追问风险点
- 自己容易忘的点

### 17.4 复盘比刷题更重要

答错题不可怕，不复盘才浪费。每次练习后至少做一件事：

- 补一条笔记
- 改一条话术
- 标一个盲区
- 重新练一次

### 17.5 面试前只看高价值内容

面试前一天不要再展开大量新知识点。优先看：

- 必深挖知识点
- 反复答错的盲区
- 项目相关话术
- 公司情报和反问素材

## 18. 数据安全与使用边界

### 18.1 本地优先

OpenJob 的业务数据主要保存在本地 SQLite 中。桌面端和手机端通过同步协议交换数据。

### 18.2 密钥保存

桌面端 API Key 会加密落盘。不要把配置文件、密钥文件或本地数据库提交到公开仓库。

### 18.3 AI 生成内容的边界

AI 生成内容可能不准确。涉及以下内容时要自行核对：

- 公司事实
- 面经来源
- 技术细节
- 简历真实性
- 项目指标

OpenJob 适合帮你组织和推进准备，不应该替代你的判断。
