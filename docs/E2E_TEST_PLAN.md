### 0.2 跳过项与原因

| 用例 | 原因 |
|---|---|
| E133 手机端「配对过但对端不可达」的降级 | **两条路都已试过并封死**：①「预置库」——`adb root` 被拒（`adbd cannot run as root in production builds`），加上 release 包不可调试，`/data/data/com.openjob.mobile` 读不到；②「真配对」——手机端同步页只有「扫描二维码配对」，**没有手动输入框**（探针实测），模拟器没摄像头。<br>剩下的唯一走法是出一个**可调试**的包（`debuggable true` 或 assembleDebug + Metro），再像桌面那样预置一条 peer 行——那是应用侧的构建决定，不在测试台范围内。未配对状态本身已由 E132c 覆盖 |
| E134b 打包态的版本闸门 | `checkPeerVersion` 在 `app.isPackaged` 为假时**故意放行**（本地两端版本号本来就不同），所以这条要起**打包产物**。用例已实现并**自跳**：`desktop/dist/win-unpacked/` 在就跑，不在就 `ctx.skip()`——本机跑一次 `pnpm package`、或 CI 的发布流水线出包之后，它会自动点亮 |

**手机端这一套怎么跑通的**：纯 adb，不需要 Maestro/Detox——`uiautomator dump` 抓界面树 →
解析 `text=` / `bounds` → `input tap`。三个坑写在 `e2e/harness/mobile.ts` 文件头：模拟器必须
`-gpu swiftshader_indirect -no-window`（否则 SystemUI 冷启动就 ANR）；dump 要 `adb pull` 回来读；
adb 的 stderr 每次都会打「1 file pulled…」，得吞掉。

**一个值得单独说的坑**：仓库里 `mobile/dist/OpenJob-1.0.0.apk` 是 **8/14 的产物**，装上去应用
永远停在「正在初始化本地数据库…」（等 4 分钟界面树一字不变，logcat 里也干净：JS 跑起来了、
expo-sqlite 加载了、没有任何异常）。换成 `gradlew assembleRelease` 当次打出来的包，5 秒就过。
所以手机端的用例要用 `E2E_MOBILE_APK` 指向当次构建的产物，别拿仓库里那份历史包当基准。

**STT 怎么自动化**：转写要加载 `Xenova/whisper-base`（约 73MB），CI 上不可能现下。用例复用
**本机已经缓存好的那一份**——把它搬进隔离副本的 `stt-models/`（transformers.js 先查
`env.cacheDir`，离线可用），本机没有缓存就 `ctx.skip()`。断言的是**通路**：模型能加载、状态
从「缺模型」走到「就绪」、一段采样喂进去拿回文本而不是抛错；识别得准不准是模型的事。
（注意不能用 `it.skipIf`：它在收集阶段求值，那时 `beforeAll` 还没跑。）

**artifact 原语怎么自动化**：它的语义就是「用户在主进程的选择器里挑一个文件」，选择器只在真人
操作时才返回。宿主留了 `OPENJOB_E2E_ARTIFACT` 注入点（见 `ipc/index.ts` 的 `e2eArtifactSelect`）：
变量只在**宿主进程**读，不是 IPC 契约的一部分，渲染层与插件页依旧传不了路径，变量没设时行为
与以前一字不差。E117 靠它验到「读进来的表被解析成 5 行 3 列」。

**配对是怎么跑通的**：发起方是手机（桌面只出二维码），桌面端因此没有「加入」入口。测试台
自己按协议来——`/sync/ping` 问版本 → `/sync/pair` 提交配对码换共享密钥 → `/sync/exchange`
带 `HMAC-SHA256(sharedKey, "deviceId|timestamp|METHOD|path|body")` 签名交换数据
（见 `e2e/harness/peer.ts`）。E131 因此能断言「桌面写一条 → 对端一次交换拿到它」，以及
「换一把密钥的请求被 401 挡掉」。

### 0.3 被真实约束推翻、已改写的设计

1. **链接仓库不能拿本地仓库当夹具**——`workspace.fetch` 只放行公网 https，回环 / 内网 /
   `file://` 一律拒（SSRF 防线，见 `desktop/src/main/plugins/pluginWorkspace.ts`）。
   E110 因此只留「拒绝路径」，真实 clone 归手工。
2. **Tavily 不可桩化**——`https://api.tavily.com` 是硬编码的，没有可配 endpoint；
   检索桩只能盖博查（它的 endpoint 在 config 里）。
3. **五个入口受原生对话框限制**，CDP 到不了：`plugin:install`（选包）、
   `pluginRuntime:artifact.read`（选表格）、`resume:importFile`（选简历文件）、
   `resume:exportPdf` / `speech:export`（选保存位置）。要自动化它们，得在主进程留一个
   「测试期自动选路径」的接缝——那是应用侧的改动，不在测试台范围内。

## 1. 目标与边界

**目标**：枚举应用全部功能点（feature point，下称 FP），每个 FP 至少有一条端到端用例，用例在真实进程、真实窗口、真实数据库上跑。

**与 §18 的分工**：

| 层 | 谁负责 | 是否在本文 |
|---|---|---|
| 纯函数 / 状态机 / 契约 / Golden | vitest（core / desktop / mobile / plugins） | 否，已有 |
| 启动链（目录 → 迁移 → IPC → 同步 → renderer） | `desktop/scripts/smoke-app.mjs`（`pnpm smoke:app`） | 纳入矩阵（BOOT-01），不重写 |
| **用户动作 → 跨进程 → 落库 → 界面回显** | 本文 | 是 |

**不做**：性能基准、压力测试、无障碍审计、安装包（NSIS）安装/卸载流程。

## 2. 分层与判据

| 层 | 内容 | 判据 |
|---|---|---|
| L0 启动 | 应用能起来、库迁移完、IPC 就绪 | `OPENJOB_SMOKE_OK` |
| L1 呈现 | 每个一级页签 / 子页签 / 插件页渲染出预期结构 | 关键控件存在且未禁用；无 ErrorBoundary 兜底页 |
| L2 流程 | 一个用户目标走完（诊断 → 计划 → 练习 → 评分 → 话术） | 界面状态变化 + 落库行 + （AI 路径）桩收到预期请求 |
| L3 失败与边界 | 缺包 / 权限拒绝 / 超限 / 模型报错 / 越界 | 界面给出明确提示且**不静默失败**；库不留半截数据 |
| L4 跨端 | 桌面写、手机读；能力缺失降级 | 两端同源结论；降级有显式状态而非隐藏 |

**确定性优先**：L1–L4 默认走 **LLM 桩**（见 §3.3），AI 路径也必须是确定性的。
真实模型只保留一组**契约冒烟**（§6），用来盯「模型输出能被读回」这类会随 Prompt 漂移的约定——这类用例不进 CI 必跑集。

## 3. 测试台

### 3.1 隔离

- 每个用例一份 `userData` 副本：`%TEMP%/openjob-e2e/<case-id>/userData`，用 `--user-data-dir` 起（**已验证有效**：副本被写入、真实 `Roaming/openjob` 不动）。
- 起之前删掉 `lockfile` / `DevToolsActivePort`，避免上一轮的残留。
- 单实例锁按 `userData` 隔离，所以用例之间、用例与用户正在跑的应用之间都不打架。
- 用例结束杀掉整棵树（`kill_shell` / 按 PID），并断言没有残留监听端口。

### 3.2 驱动

CDP（`--remote-debugging-port=<port>`）+ Node 全局 `WebSocket`，不引入 Playwright：

- 主页 target（`type: 'page'`）→ 点导航、填表单、读 DOM；
- 插件页在沙箱 iframe（`type: 'iframe'`，`about:srcdoc`）里，**必须单独连一个 target**；
- 等待用轮询 + 超时，不用固定 sleep；每次点击前断言控件可见且未禁用。

已跑通的最小骨架见 §7（上一轮的临时代码，落地时抽成 `e2e/` 下的 driver）。

### 3.3 LLM 与外部服务桩（关键设计）

`config.json` 里的 provider `baseUrl` 与检索 endpoint 都是可配的——**把隔离副本的配置指向本地桩服务器**，就得到一条完全确定性的 AI 路径，不需要改应用一行代码：

| 桩 | 冒充 | 命中判据 | 返回 |
|---|---|---|---|
| `openai-compatible` | 模型 Provider | 请求体里的 system 片段 / `promptId` | 固定 JSON：出题 `{title, scenarioMd}`、评分 `{feedbackMd, improvedOutlineMd, dimensions[]}`、讲解 `{markdown}`、结构 `{sections}`… |
| `search` | 博查 / Tavily | 请求 URL 路径 | 固定检索结果（含可信度、发布时间） |
| git | `workspace.fetch` 的远端 | `url` | **不可桩化**：宿主只放行公网 https，本地裸仓库与 `file://` 一律拒。clone 归手工，E2E 只测拒绝路径 |

桩要落**请求日志**（promptId、user 文本摘要、时间），作为第三条断言面。

这样收敛的收益：用例可断言「评分请求里确实带了 4 个 dimensionId」「出题请求里带了问 JSON 结构那一段」（就是上一轮修的那个 bug，它会变成一条**常驻回归用例**）。

### 3.4 夹具

`seed.sqlite`（一场备考 + 岗位 + 一份简历 + 考点树 + 已确认证据 + 一条已评分 attempt）、`fixtures/repo.git`（本地裸仓库，含 >200 个文件与嵌套目录 / 符号链接 / 大文件）、`fixtures/table.csv`（含重复列名、断行等坏样本）、`fixtures/resume.pdf|docx|txt`、`fixtures/audio.wav`。

### 3.5 三条断言面

1. **界面**：DOM 文本 / 控件状态 / 计数变化；
2. **落库**：用例结束后直接读该副本的 `openjob.db`（`better-sqlite3`），断言行、状态、外键；
3. **桩日志**：AI / 检索请求的次数与内容。

「界面看起来对」不算通过——L2 以上必须至少两条面同时成立。

## 6. 真实模型契约冒烟（不进 CI 必跑集）

只保留三个用例，用真实 Provider 跑，盯 Prompt 与读回契约的漂移：

- **R1 出题读回**：基线自我介绍与 `se.*` 各一次 → 模型返回能被 `readGeneratedQuestion` 读回。
- **R2 评分读回**：4 个维度齐全且引文能在作答里定位（就是上一轮 3.5/5 那次）。
- **R3 讲解与结构化**：能读回 markdown / sections。

跑法：`E2E_LIVE=1 pnpm test:e2e cases/live`。本机要有真实的 provider 配置——密钥不经过测试
进程：把本机真实的 `config.json` / `secrets.json` / `Local State` 搬进隔离副本，应用自己用
safeStorage 解开（OSCrypt 密钥就在 `Local State` 里）。任一条不满足整组自跳，失败不阻塞合并，
但每周至少跑一次。

实测（本机 agnes-2.5-flash）：R1 出题读回 3.2s、R2 评分读回 57.6s（四维全对齐）、R3 讲解与
结构化 51.2s，三项全过。
